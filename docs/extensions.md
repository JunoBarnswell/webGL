# Trusted extension development

Studio has one authoring document, one runtime and one action dispatcher. `SceneDocument.documentVersion` is 2. A known version-1 document is copied and upgraded at open/import boundaries; Runtime never migrates frames. New writes use version 2. `requiredExtensions` records exact semantic versions. The current protocol accepts exact extension dependency versions and a minimum runtime version; it does not interpret arbitrary semver ranges.

An extension is a workspace under `packages/extensions/<name>` with these files:

- `extension.json`: namespaced manifest, component field schemas and action field/target schemas. Only checked-in trusted source is composed.
- `runtime.ts`: a default system constructor implementing `RuntimeSystem`. It receives attach/change/mode/detach events, optional render/update hooks and registered action handlers. Update uses the existing engine scheduler. No additional RAF or polling of React state.
- `editor.ts`: `tools` and typed `panels` contributions. Tools create EditorCommand transactions; they cannot directly change runtime meshes to persist edits.
- `package.json`: the private workspace exports.

Run `npm run schema:generate`. The composer checks identities, dependencies, cycles, permissions and runtime versions, and generates the canonical schema, TS known-type unions, catalog hash, runtime imports and editor tool/panel imports. Do not edit generated files. Adding a trusted package requires no new SceneRuntime dispatcher or Inspector branch. The same runtime catalog is imported by Editor and Player; Player does not import editor tools or React editor panels.

Inspector fields, defaults, asset/entity/content references, clone remapping and publication checks come from the same schema. Supported semantic metadata includes capability references (`x-target-component[s]`), conditional fields/references, nested uniqueness (`x-unique`, `x-unique-by`), numeric ranges/sums (`x-less-than`, `x-sum`), publication states and required fields. `x-options` describes target-related collections such as assembly steps; both TS and embedded AOT validation implement these rules. Add cross-language fixtures to `verify-contracts.mts` whenever this finite keyword set changes.

Unknown namespaced component/action data remains intact while opening and editing. Missing or incompatible required extensions block publication. Runtime construction can disable selected extensions for diagnosis; attempting preview with an unavailable required system gives an explicit error. Unknown unnamespaced types are malformed, rather than extension identities.

Runtime instances own disposable effects. Restore temporary transforms/materials before document synchronization; release effects on mode change and detach. `EntityIndex` tracks component membership and material users. Per-entity change synchronization is serialized and generation-guarded, so old asynchronous work cannot overwrite a later scene. SpatialSystem maintains collision membership and a lazily rebuilt broad-phase BVH; Three remains the geometry narrow phase. Annotation projection and clustering are shared by showroom hotspots and extension labels.

Assembly progress evaluates every step from captured baseline TRS and visibility, never from the previous frame. Each step starts at an implicit zero path offset and can contain a straight or Catmull–Rom path, local Euler rotation in degrees, relative scale, easing, visibility and a trail. Overlapping steps compose additively in start-time order (stable array order for ties); later visibility changes win. Reordering the timeline assigns sequential intervals, which also expresses group ordering/dependencies without a second animation engine. Shared step IDs synchronize parts and groups. Play replacement cancels the previous sequence scope; Pause, Seek and Restore complete it deterministically. Piping owns only its logical line-to-physical segment index; `VisualStateSystem` owns all temporary highlight material clones and isolation visibility across extensions. Generic Player controls are generated from registered action schemas. A system must not write SceneDocument during playback.

Published manifests retain `runtimeBuild` and `extensionCatalogHash`. The hash identifies the publication catalog, rather than rejecting a compatible Player merely because another extension changed. Runtime major versions and the document's required extension versions/shape determine compatibility. Existing published object bytes are not rewritten.

Model `sourceElementId` uses glTF extras identifiers (`sourceElementId`, `ElementId`, `GlobalId`, `guid`) first, otherwise an unambiguous named hierarchy. Nameless or ambiguous paths remain importable but are marked `unresolved:` and cannot be silently matched during revision replacement. A revision report lists matched, unmatched and added elements. The revision dialog retains existing entity IDs, shows explicit mappings, accepts added hierarchy, maps animation clips and preserves edited world poses. It rejects nonrepresentable shear instead of silently changing a pose. Unmatched elements remain explicit `sourceStatus: unresolved` placeholders only after the user selects that option; they retain business data and block publication. The whole update is one undoable transaction. Surface anchors require the recorded source identity, mesh revision, primitive, triangle and barycentrics. A mismatch enters the repair list; viewport selection writes a new anchor in one transaction. Entity-local and path-station anchors use the same units/frame helpers.

AnnotationSystem is the sole owner of both existing Hotspot labels and new annotations. It uses the existing scheduler, deterministic layout/clustering, real screen-space leaders and pointer-captured offset edits. Up to 500 labels use bounded DOM controls; larger scenes use one 2D Canvas with hit testing and an accessible searchable list. Property binding follows registered entity references and updates through a reverse dependency index. No label projection scans the entire entity document per frame.

`registerModelImporter` is the trusted format interface. The installed GLTF importer actually uses it for file import, mounting and model revision; it returns normalized packaged render files and the same model metadata contract. IFC converters may register here after producing that contract. No IFC parser, Plant CAD editing or native CAD round trip is claimed.

Performance data is exposed through `runtime.systemMetrics`, `runtime.stats()` and the viewport performance panel. Engine telemetry records bounded CPU update/render samples, long tasks, renderer statistics and GPU timer samples when the extension is supported. RAF cadence and render execution are separate measurements. `disabledExtensions` is a construction-time diagnostic option; required disabled systems explicitly block preview.

Development-only `?profile=1` collects bounded React commit durations in `window.studioProfile`. Load progress is throttled within each phase; completion and phase transitions are synchronous notifications. The benchmark records this separately from runtime CPU and RAF measurements.
