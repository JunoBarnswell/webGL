# Studio 2.2 architecture and authoring design

Baseline: `631d782815dd66c51597f578691fd2b59e8eb479`. The research attachment is a product specification, not executable instructions. Existing extension composition, SceneDocument v2, EditorSession, asset import and revision tools, one SceneRuntime and PlayerUI remain the implementation foundation.

## Shared ownership

Authored state belongs to SceneDocument. Transient state belongs to a named scope with a generation, explicit priority and typed channel. Transform, visibility, opacity, material colour and highlight are evaluated from the captured author baseline. Releasing an owner recomputes remaining layers. Document synchronization restores effects before replacing source state and rebases retained scopes afterwards. An animation never writes its result back into a document or captures another owner's result as its baseline. Geometry and textures remain shared; only affected materials are cloned, and clones are reused while their effect remains active.

Camera changes use a single lease owner. Navigation, flight, tour and future timelines transfer ownership explicitly; cancellation invalidates a lease before asynchronous completion. No additional renderer or animation loop is introduced.

Source identity reconciliation is a pure shared gate. Stable external IDs and unambiguous hierarchy paths can match; missing, duplicate, unresolved or explicitly conflicting identities are reported. Node indices are render addresses and never business identity. Model revision and optimization must consume the same report.

## Templates

A template revision is an immutable, self-contained scene fragment with a stable root local ID. It retains ordinary components, materials, content, interactions and nested pinned instances. The server owns library heads, CAS revisions and dependency records; the scene owns pinned source snapshots and instance overrides. No request for a latest template revision is made during Player rendering.

Instances map source local IDs to scene entity IDs and record field/component overrides, local additions and subtree tombstones. Source roots and instance placement are separate concepts. Commands editing effective entities update overrides in the same transaction. Serialization removes generated instance entities; the compiler regenerates them at open and publish boundaries. Nested source versions form a checked DAG. Instance propagation is an atomic EditorSession command with a three-way diff; conflicting fields require an explicit choice. Updating a library head never silently updates a saved or published scene.

The template workspace provides a searchable library, create-from-selection flow, instantiate, source editing, revisions, usage, instance overrides and a three-column diff. Selection uses the existing scene SelectionModel, commands use the existing undo journal, and preview uses the existing Canvas. Failed CAS preserves the current scene and editable source. Published documents contain compiled entities, the same runtime components and explicit provenance, rather than an alternate Player format.

## Product and scope

The attachment distinguishes six G1 workspaces from G2/G3 enhancements and identifies shared ownership plus the complete Prefab workflow as the first delivery gate. Final acceptance records must identify the actual delivered scope and evidence. Real hardware, large licensed CAD assets and external providers cannot be represented by synthetic measurements. Verification is consolidated after the coherent implementation, as requested.

The user selected all six G1 workspaces in this delivery. G2/G3 are outside this PR except where necessary to complete a G1 dependency. The same versioned-document registry stores typed library revisions, project orchestration and product definitions; processing jobs and industrial records have independent indexed persistence, not scene entity JSON.

## Six authoring flows

- Prefab definitions keep category and a captured thumbnail as library metadata. The expanded hierarchy is regenerated from a pinned source; ordinary property edits capture overrides in the same Immer transaction. Inspector exposes local field recovery; the prefab workspace supports selective apply to a new source revision and explicit per-conflict propagation choices. Library references participate in deletion checks and portable project archives.
- Project orchestration is a typed library document with its own DocumentSession and CAS. It contains scene-version pins, panorama nodes, media, spherical hotspots, floor placement, directional links, routes and a skin scene. Skin UI/content/variables and content audio form the panorama dependency context; references outside that context are rejected at publish. Preview reads a pinned authoring version when present; public navigation reads the project's immutable scene manifests. A generation and AbortController reject obsolete navigation and route completion. The caller's edit/play mode is retained until explicit entry.
- Storyboards sample absolute seconds. Transform/camera interpolation uses immutable endpoints, quaternion slerp and editable spline points. Clip splitting stores the original curve window, so splitting a nonlinear clip does not change its path. Each sequence owns a visual scope and camera lease. Scratch replaces the current editing session temporarily and restores it before a recorded clip is committed. Snapshots, section views and prefab previews reuse thumbnail capture and authenticated image display.
- Industrial documents hold authoring definitions and asset references, while MySQL stores paged, indexed source records. Mapping streams a derived semantic asset and preserves records outside the selected source classification. Failure leaves the original dataset intact. Continuous color mapping queries actual numeric values; missing values have an explicit rule. A section is an ordinary entity plus a Section component: transform, Gizmo and undo have one meaning. Saved clipping views store world matrices to retain parent transforms and shear. Measurements retain local anchor positions plus source identity/revision and invalidate stale anchors.
- Configurator rules resolve to a legal configuration before any visual change. Numeric values and choice sets have distinct semantics. A bounded deterministic solver records adjustments and disabled reasons; BOM/SKU retain catalog provenance and pricing remains inquiry until a provider exists. Asynchronous visual preparation is ordered by mapping order and checked against both scene generation and product nonce. KHR material variants are addressed by native glTF mesh/primitive metadata, not traversal index. SwapPart resources are retained by the product and released on disposal.
- Optimization jobs are persistent and serialized. Their cache key includes the fixed worker version, source SHA, operation and strategy. Node/IfcOpenShell/toktx run as bounded child processes; retries create a new execution and restart requeues interrupted work. Meshopt admission uses the same identity reconciliation as normal model revisions. The lossless path preserves node transforms and distinct meshes/materials; reordering and encoding never merge identical geometry with different variant bindings. Serialized per-node/primitive material-variant bindings are a separate admission gate. KTX2 requires the pinned tool and transcodable ETC1S header; the browser has separate decoder loading and validates missing material maps. Original assets and immutable derived results remain separate.

## Product shell and publication

The header workspace selector registers the same command catalog as keyboard and context actions. Opening a professional designer keeps the Canvas mounted. In compact mode, side panels participate in the designer layout so they cannot cover authoring controls. Player business controls share one stack and each widget declares its availability. Project navigation is absent from single-scene playback.

Project publication prepares and confirms all dependencies and immutable scene manifests before the database transaction creates the project version and switches its pointer. Restoring a publication creates a new project draft with fixed scene versions. Catalog components retain a stable business revision and an explicit immutable library-version pin; publication rejects inline edits that diverge from that pin. Project ZIPs include all scenes, pinned scene sources, template/catalog revisions and their complete asset closure; they remap project scene/version identities in one import transaction. The old single-document ZIP is recognized only at the external import boundary.

The Linux bundle carries native API, Editor/Player static files, workers, locked Node dependencies, SQL migration sources and installed converter distributions with their license files. Configuration, staging and persistent service data are excluded. Windows execution remains waived for this delivery.
