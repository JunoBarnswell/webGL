# Studio 2.3 asset admission and later performance stages

G1 is the implemented path: immutable source → identity-preserving Meshopt/optional BasisU encoding → structural diff → budget report → fenced output ledger → explicit document revision application. Settings are canonical (sorted unique protected IDs, explicit nullable budget fields) and hashed with worker recipe `2.3.0:2`. GPU texture allocation is a conservative RGBA8/full-mip estimate, not measured VRAM. Exceeding a configured limit produces `UnmetBudget`; no automatic simplification or material merging is performed. A scene explicitly pins each asset's completed job in `settings.processingReports`; authoritative checks read the committed job/output ledger from MySQL and verify the asset and settings hash, never a client-supplied “passed” flag or another project's latest job. Exported project pins require the same ledger or a rerun on the destination backend. Missing reports follow the authored advisory/required policy; known unmet limits block a new release.

| Stage | Admission conditions before implementation | Current support |
|---|---|---|
| G2 geometry instancing | Identical geometry/material/skin contract, one source ID per instance, picking and semantic-row lookup retain instance identity; independently check negative scales and instance transforms | Research only; no automatic conversion |
| G2 optional LOD | Original IDs map to every LOD, anchors remap explicitly or block; validate silhouette, material/variant/skin and animation equivalence; authored error metrics and target hardware thresholds | Research only; no runtime LOD switching introduced |
| G3 chunk/priority streaming | Immutable manifest dependency closure, explicit world origin, cancellation/generation ownership, bounded residency and stable semantic indices; interruption must retain prior usable state | Research only; no scene streaming introduced |

The default remains ratified `EXT_meshopt_compression`. A newer extension name is not substituted merely because it is newer. KTX2 conversion uses pinned KTX-Software 4.4.2 and rejects a texture shared between linear and sRGB slots. Unknown source extensions, changed variant bindings, node/world matrices, skin/animation contracts and lost protected identities prevent successful processing. Topology changes are separately disclosed when lossless index reorder is requested; the editor blocks reorder for bound surface-triangle anchors.

Workers claim rows with `FOR UPDATE SKIP LOCKED`, a 15-second lease based on `UTC_TIMESTAMP(6)`, and an incrementing epoch. Heartbeat runs every two seconds. Progress, completion and dependency writes require that exact live owner/epoch. Result rows and dependencies commit together; content-addressed uploads from an expired attempt may remain unreferenced and cannot become a logical job result. Attempts write to `job/epoch`; startup does not reset another instance's running jobs. Cancellation and expiry terminate the owned execution; a killed API's abandoned subprocess cannot commit database results. Reclaimed jobs run in a separate attempt directory. Unreferenced staged objects may be reclaimed by a future retention policy; no user asset/history is deleted by job recovery.
